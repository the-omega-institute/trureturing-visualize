These counts are not theorems, and the page does not rerun Lean; “frozen” only means that a state file exists, which is exactly the repository’s definition of frozen membership. Resolution kinds (proved or refuted) are today’s records in the Scribe sources.

理论接口 · 这个页面在数什么Theory interface · what this page counts

trureturing 把整个系统当作一张只增不减的真值图：节点是命题，边是证明依赖。Lean 内核验证过的声明一旦冻结就永不解冻；理论卷只是参考输入，经摄入变成 atom，再一条条被形式化结果覆盖。这个页面不读任何证明，只看这张图在 git 历史里每天长成什么样。

  1. 快照。dev 分支从 2026 年 7 月 10 日到 10 月 28 日共 111 天，日期一律按 UTC。每天取当天最后一个 first-parent 提交（即最后一次合并后的状态），列出它的文件树。“合并数”是到那天为止的 first-parent 提交数。提交者分布在多个时区，按各自时区的日期分天会让日期在 first-parent 链上前后颠倒，UTC 时间戳则是单调的。
  2. Lean 模块。D5/**/*.lean 的文件数，按第二级目录分层（S0 载体、S1、S3 等），按第三级目录分领域。Lean 是唯一的数学真源。
  3. 冻结。仓库规定：Golden/Frozen/state/<模块>.lean.json 存在，该模块就是冻结成员。状态片从 9 月 4 日开始出现；8 月 13 日到 10 月 11 日之间还有旧格式的 accepted 事件文件（以内容哈希命名）。页面在有状态片的日子数状态片，此前数事件文件。
  4. 消化账目。理论卷（docs/develop/theory）经摄入切成 atom，存入内容寻址的 Meta/Digestion/atoms。每个 atom 的账目条目在四个目录之一：residual-open（还没有覆盖）、partial-closed（部分覆盖）、absorbed-closed（由冻结声明覆盖）、nonpropositional-inapplicable（凭收据结算：不是命题，或只由上游库闭合）。冻结与消化是两个独立的状态：定理冻结了，它对应的 atom 不一定已经闭合。
  5. 开放问题。Problems/*.md 每份卷宗对应一个已发表的猜想或问题，附逐字出处与文献核对。Blueprint 的 Scribe 源码为结算了的问题记录 ResolutionKind：Proved 或 Refuted。页面按卷宗第一次出现在 dev 上的日期排进日历，颜色取今天的记录。
  6. 边界。计数只说明文件存在，不说明内容的难度或价值；记账规则的变化（格式迁移、结算收据）会让曲线跳变。这些都在读数旁边注明。

trureturing treats the whole system as a truth graph that only grows: nodes are propositions, edges are proof dependencies. A declaration verified by the Lean kernel is frozen and never unfrozen; theory volumes are only reference input, ingested as atoms and then covered one by one by formal results. This page reads no proofs; it only shows what the graph looked like on each day of the git history.

  1. Snapshots. The dev branch from July 10 to October 28, 2026: 111 days, all dates in UTC. For each day the page takes the last first-parent commit (the state after the day’s last merge) and lists its file tree. “Merges” is the number of first-parent commits up to that day. Committers work in several time zones; dating commits in each committer’s own zone would put dates out of order along the first-parent chain, while UTC timestamps are monotonic.
  2. Lean modules. The number of files D5/**/*.lean, split into strata by the second directory level (S0 carrier, S1, S3, …) and into areas by the third. Lean is the only source of mathematical truth.
  3. Frozen. The repository’s rule: a module is a frozen member when Golden/Frozen/state/<module>.lean.json exists. State files appear from September 4; between August 13 and October 11 there are also accepted event files in an older format (named by content hash). The page counts state files on days that have them, and event files before.
  4. The digestion ledger. Theory volumes (docs/develop/theory) are ingested and cut into atoms, stored content-addressed in Meta/Digestion/atoms. Each atom’s account entry sits in one of four directories: residual-open (not yet covered), partial-closed (partly covered), absorbed-closed (covered by frozen declarations) and nonpropositional-inapplicable (settled by a receipt: not a proposition, or closed by an upstream library only). Frozen and digested are separate states: a frozen theorem does not mean its atom is closed.
  5. Open problems. Each Problems/*.md dossier is a published conjecture or question with its verbatim source and a literature check. For a settled problem, the Scribe sources of the Blueprint record a ResolutionKind: Proved or Refuted. The page places each dossier on the calendar by the day it first appeared on dev, coloured by today’s record.
  6. Limits. A count says that files exist, not how hard or valuable their content is; changes in bookkeeping (a format migration, settlement receipts) make the curves jump. The readouts point these out.
